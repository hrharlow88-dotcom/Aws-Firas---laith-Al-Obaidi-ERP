# مجموعة ليث العبيدي للسيارات — نظام الإدارة

نظام ويب عربي باتجاه RTL. التنفيذ الحالي يغطي تسجيل الدخول والأدوار والفروع ودليل الموظفين، إضافة إلى إدارة أساسية لطلبات الإجازات والموافقات والأرصدة. تبقى الرواتب والمحاسبة والحضور وعمليات السيارات مراحل مستقلة غير منفذة.

## التشغيل المحلي باستخدام Docker

1. انسخ `.env.example` إلى `.env`.
2. حدّث `ADMIN_EMAIL` إلى بريد مسؤول الشركة، وغيّر `DB_PASSWORD` و`JWT_SECRET` و`ADMIN_PASSWORD` إلى قيم عشوائية خاصة بك. يجب أن تكون كلمة مرور المدير 12 محرفاً على الأقل وسر JWT 32 محرفاً على الأقل.
3. شغّل `docker compose up --build`.
4. افتح `http://localhost:3000` وسجّل الدخول بالبريد وكلمة المرور اللذين وضعتَهما في `.env`.

تنشأ قاعدة PostgreSQL دائمة في مجلد Docker volume. لا تستخدم بيانات `.env.example` كما هي، ولا تعرض الخدمة على الإنترنت دون TLS ونسخ احتياطي مُدار وتغيير بيانات الدخول الافتراضية.

## تجربة مؤقتة على Render عبر GitHub

يحتوي المستودع على `render.yaml` لنشر الواجهة وواجهة API في خدمة Node واحدة مع PostgreSQL خاص داخل Render، دون تشغيل Docker. بعد دمج التغييرات إلى الفرع الافتراضي:

1. سجّل الدخول إلى Render واربط حساب GitHub.
2. اختر **New > Blueprint**، ثم حدد هذا المستودع والفرع الافتراضي.
3. أدخل `ADMIN_EMAIL` وباسورد إداري قوي (12 محرفاً على الأقل) في شاشة Render، ثم أنشئ موارد التجربة.
4. انتظر نجاح فحص `/api/health` وافتح رابط خدمة الويب الذي يعرضه Render.

هذا الإعداد يستخدم الخطة المجانية للتجربة فقط: خدمة الويب قد تنام عند عدم الاستخدام، وقاعدة PostgreSQL المجانية تنتهي بعد 30 يوماً ولا توفر نسخاً احتياطية. استخدم بيانات تجريبية فقط؛ لا ترفع أسماء أو رواتب أو بيانات شخصية فعلية. للإنتاج، غيّر الموارد إلى خطط مدفوعة، اضبط النسخ الاحتياطي وسياسات الوصول، وراجع الامتثال والصلاحيات قبل استيراد أي بيانات حقيقية. لا يتضمن `render.yaml` كلمات مرور أو أسراراً ثابتة.

## وحدات المرحلة الأولى

- **نظرة عامة:** أعداد الموظفين والفروع النشطة مع أحدث سجلات التعيين.
- **الفروع:** إضافة موقع برمز فريد وربط الموظفين به.
- **الموظفون:** البحث والإضافة وتحديث حالة العمل.
- **المستخدمون والصلاحيات:** حسابات منفصلة بأدوار مدير النظام، الموارد البشرية، المالية، مدير الفرع، والمشاهدة فقط.
- **ضوابط الوصول:** يتحقق الخادم من كل طلب؛ مدير الفرع محصور بفرعه، وبيانات الرواتب غير موجودة في هذه المرحلة.
- **أمان الحساب:** كلمات المرور مشفّرة بـ bcrypt، الجلسات قصيرة الأجل وقابلة للإبطال عند تغيير كلمة المرور أو تعطيل الحساب، مع سجل تدقيق للعمليات الحساسة.
- **مركز إعدادات النظام:** بيانات الشركة، أنواع الإجازات واستحقاقاتها القابلة للتحديد، ترتيب الموافقات، أسماء الأدوار وصلاحياتها، وحقول الموظف الإضافية. إدارة الإعدادات لمدير النظام، وتُسجل التغييرات في سجل التدقيق. صلاحيات مدير النظام الأساسية ثابتة.
- **حقول الموظف الإضافية:** تُعرّف من الإعدادات وتظهر في نموذج الإضافة وتُخزن مع سجل الموظف؛ التحقق من القيم يجري في الخادم.
- **إعدادات الرواتب التمهيدية:** يتيح مركز الإعدادات تعديل العملة الأساسية وقاسم الشهر ودقة التقريب ومكونات الاستحقاق والاستقطاع وطرق احتسابها. القيم الأولية مستوحاة من ملفات الرواتب؛ لا تُستورد بيانات شخصية أو مبالغ من تلك الملفات. مكوّن الضمان الاجتماعي غير مفعّل حتى المراجعة والاعتماد القانوني. هذه المرحلة لا تنشئ مسيرات رواتب ولا تنفذ دفعاً؛ يلزم استكمال ملفات الموظفين المالية، الاستيراد بمعاينة، الحسابات والاعتماد قبل التشغيل.
- **الإجازات:** تقديم طلبات الأيام أو الساعات، منع تداخل الفترات، مسار موافقات متعدد الخطوات، إلغاء الطلبات، أرصدة قابلة للتعديل عبر دفتر حركات غير قابل للاستبدال، وسجل تدقيق. تُقيّد طلبات مديري الفروع بموظفي فروعهم.

يُنشأ أول حساب مدير مرة واحدة من متغيرات البيئة عند تشغيل الخادم لأول مرة. إدارة الحسابات الإضافية تتطلب صلاحية إدارة المستخدمين؛ منح هذه الصلاحية لا يسمح بإنشاء أو ترقية حساب إلى مدير نظام.

**سياسة الإجازات وحدود التنفيذ:** زر «تحميل سياسة الشركة» يضيف إلى إعدادات المدير الإجازة الاعتيادية (21 يوماً، ثم 23/25/28 يوماً عند 6/11/16 سنة خدمة)، المرضية (30 يوماً مع طلب مرجع التقرير الطبي)، الولادة (14 أسبوعاً مدفوعة/98 يوماً تقويمياً)، والزمنية (3 ساعات للطلب، مرتان و6 ساعات شهرياً، الجمعة عطلة أسبوعية). ويقترح موافقة مدير الفرع ثم مدير الموارد البشرية إذا لم يكن هناك مسار محفوظ مسبقاً. يلزم حفظ الإعدادات صراحة. لا تُنشأ أرصدة تلقائياً: الاستحقاقات السنوية المعروضة مرجعية ولا تضاف إلى دفتر الرصيد؛ يجب إدخال رصيد افتتاحي/تسوية قبل طلب الإجازات المستقطعة. مرجع التقرير الطبي النصي لا يغني عن فحص المستند من الموارد البشرية، ولا يدعم النظام رفع ملف طبي بعد.

ينص ملف الشركة على 90 يوماً غير مدفوعة للأمومة؛ لم يُفعّل هذا الحكم، لأن المادة 87 من قانون العمل العراقي رقم 37 لسنة 2015 تقرر 14 أسبوعاً مدفوعة. يُسجل التعارض للمراجعة القانونية، ويجب التحقق من التطبيق على جهة العمل والنص القانوني الساري قبل الإطلاق. أنواع الإجازات الخاصة بالوفاة والزواج والعدة، وحد الاستخدام لمرة واحدة للحج/العمرة، واحتساب الإجازات غير المدفوعة، ما زالت تحتاج قواعد أهلية/توثيق منفصلة. كما لا يدعم النظام حالياً الرواتب أو استقطاع الإجازات غير المدفوعة. راجع أيضاً التعارض الوارد في ملف Excel بين 15 و30 يوماً مرضياً وتراكم 180 يوماً قبل اعتماد أي استحقاق.

## التطوير

```powershell
Copy-Item .env.example .env
docker compose up -d database
```

يتطلب تشغيل خدمات التطوير محلياً Node.js 22+ وPostgreSQL. أنشئ `backend/.env` باستخدام الإعدادات المحلية، ثم شغّل `npm install` و`npm run dev` داخل `backend`، وشغّل `npm install` و`npm run dev` داخل `frontend`. واجهة Vite تمرر `/api` إلى المنفذ 5000.

## البيانات المرفقة

نماذج Excel والعقود وملفات HTML المرفقة استُخدمت كمرجع للمجالات واللغة والواجهة فقط. لم تُنسخ بيانات الموظفين أو الرواتب إلى قاعدة البيانات. دليل الاستيراد يوضح نطاق المرحلة الحالية والخطوة التالية.
